## Executive orientation

The explorer is a **static, bundler-free, single-page CesiumJS app**. Three files are authored (`index.html`, `style.css`, `app.js`); four are generated by `python -m fcf3d.build_sites` (`sites.geojson`, `sites.json`, `sites.inline.js`, `manifest.json`); twelve are generated by `python -m fcf3d.build_models` (`web/models/*.glb`). There is no build step, no package.json, no lockfile, no vendored Cesium. The only runtime third-party dependency is CesiumJS pulled from unpkg at page load.

The data it renders is **legacy_v2 fixture output** - `manifest.json` line 8 names `fixture_legacy_v2_site_results.csv` - and **the viewer never tells the user that**.

#### Cesium CDN reference - what is actually true

The task brief located this in `app.js`. **It is not in `app.js`.** `app.js` has no CDN reference at all; it consumes a `Cesium` global declared at line 12 (`/* global Cesium */`). Both CDN references live in `index.html`.

The brief's substance is nevertheless correct:

| | Location | Text |
|---|---|---|
| Comment | `web/index.html:9–12` | `CesiumJS from CDN. Google Photorealistic 3D Tiles require 1.124 or later. / For a reproducible build, pin the version: / https://cesium.com/downloads/cesiumjs/releases/1.128/Build/Cesium/Cesium.js / and vendor it into web/vendor/ for offline demos.` |
| Actual JS | `web/index.html:117` | `<script src="https://unpkg.com/cesium/Build/Cesium/Cesium.js"></script>` |
| Actual CSS | `web/index.html:14` | `<link href="https://unpkg.com/cesium/Build/Cesium/Widgets/widgets.css" rel="stylesheet">` |

**The URLs are unpinned.** They carry no `@version` specifier, so unpkg resolves them to the npm `latest` dist-tag. I verified this live:

```
$ curl -sI -L https://unpkg.com/cesium/Build/Cesium/Cesium.js
HTTP/2 302
location: /cesium@1.143.0/Build/Cesium/Cesium.js
cache-control: public, max-age=60, s-maxage=300
```

- **Does the current reference satisfy the ≥ 1.124 constraint?** Yes - *today*, incidentally. It resolves to **1.143.0** (confirmed against `https://registry.npmjs.org/cesium/latest`). It satisfies the floor only because `latest` happens to be above it; nothing in the repo enforces it. The redirect is cached for 60 seconds, so the served version can change between two page loads with no repo change.
- The comment recommends pinning to **1.128** from `cesium.com/downloads`, a **different host** from the one actually used (`unpkg.com`), and recommends vendoring into `web/vendor/` - **`web/vendor/` does not exist**; the only directories under `web/` are `data/` and `models/`.
- Neither reference has an `integrity` (SRI) attribute or `crossorigin`, so there is no tamper detection on a third-party script that gets full DOM access.
- I verified the three Cesium factory functions app.js calls still exist in current CesiumJS: `createGooglePhotorealistic3DTileset(apiOptions, tilesetOptions)` (async, returns `Promise<Cesium3DTileset>`), `createWorldTerrainAsync(options)`, `createOsmBuildingsAsync(options)`. The zero-argument call at line 208 remains valid - the 1.125 deprecation / 1.126 removal only affected the *positional* form `createGooglePhotorealistic3DTileset(key)`, not the options-object or no-argument form. **So the API usage is not broken**, but current Cesium emits a one-time console warning when `onlyUsingWithGoogleGeocoder: true` is not passed to `apiOptions`, which `app.js` does not pass.

#### Cesium ion token handling

- **Where the token comes from:** `localStorage` key **`fcf3d.ionToken`**, read at `app.js:879` via the `store` shim (lines 71–74, which swallows `SecurityError` in sandboxed contexts). Written at line 887 from `#tokenInput`. Applied at line 145: `Cesium.Ion.defaultAccessToken = token`.
- **Is any token value present in the file?** **No.** There is no literal token in `app.js`, `index.html`, `style.css`, `manifest.json`, or any of the three data files. The only token-shaped string in the tree is the `placeholder` attribute at `index.html:102` (`eyJhbGciOiJIUzI1NiIsInR5cCI6...`), which decodes to the JWT header fragment `{"alg":"HS256","typ":` and has no payload or signature. **No security finding here - the repo is clean**, and this matches `CLAUDE.md` non-negotiable #5 ("No secrets in the repo. The Cesium ion token is entered at runtime and held in the browser only.").
- **What the no-token / Flat fallback does** (`initViewer`, lines 178–183): when `state.hasToken` is false it disables every `#basemapSeg` button whose `data-mode !== 'flat'` and calls `setMode('flat', { silent: true })`. `setMode` for `flat` (line 226) just installs `EllipsoidTerrainProvider` - a smooth WGS-84 ellipsoid with the OSM raster base layer draped on it. The GLB massing and all 12 markers still render, so the claim in the gate copy ("every site, score, and proposed build is fully usable") is accurate. Guard at lines 192–195 also blocks mode changes with the toast `That base map needs a Cesium ion token. Reload and add one to enable it.`
- **There is no UI to clear or replace a stored token.** Once `fcf3d.ionToken` is set, the gate never appears again (line 880 returns early) and the toast at line 193 tells the user to "Reload and add one" - which will not work, because a reload takes the stored-token path. A user who saves a bad/expired token is stuck without opening devtools.

Each has 1 mesh and 1 node; 9 materials on the nine larger models and 8 on PWC003/PWC005/PWC008. Filenames are `FFX001–004.glb` and `PWC001–008.glb`; **every `site_id` in `sites.geojson` has a matching model file** - the `models/${site_id}.glb` URI at `app.js:315` resolves for all 12. ## FINDINGS

Ordered roughly by consequence.

**F1 - Horizon-convention violation, unlabelled: the viewer shows 2035 and 2050 port targets. (HIGH)**
Canonical is 2026/2036/2046/2056. The Right-sizing tab renders `<dt>2035 (base / high)</dt>` (`app.js:593`) and `<dt>2050 (base / high)</dt>` (`app.js:594`); the compare modal renders `Ports 2035 (base)` and `Ports 2050 (base)` (`app.js:763–764`); the left rail renders `${p.ports_now}→${p.ports_2050} ports` on every row (`app.js:416`); and the sort dropdown offers `By 2050 port need` (`index.html:59`). The underlying keys are `ports_2035`, `ports_2050`, `right_sizing.ports_2035_base/high`, `right_sizing.ports_2050_base/high` in `sites.geojson`. **Nothing in the UI labels any of this legacy_v2.** The source manifest does say the right-sizing table is `fixture_legacy_v2_right_sizing.csv` (`manifest.json:9`), so the data is genuinely legacy - but the presentation is stale text that forgot to say so.

**F2 - Internal contradiction inside one panel: 2035/2050 above, 2026/2036/2046/2056 below. (HIGH)**
In the same "Right-sizing" tab, the `<dl>` at `app.js:591–597` shows 2035/2050, and the Scenarios table immediately beneath it (`app.js:609–610` → `scenarioTable`, line 471, rendering `s.horizon_year`) shows **2026, 2036, 2046, 2056** - canonical. A planner reading one panel sees four different horizon years and two incompatible conventions with no explanation.

**F3 - The viewer never discloses that it is showing legacy_v2 fixture data. (HIGH)**
`sites.geojson` → `metadata.sources` names `fixture_legacy_v2_site_results.csv`, `fixture_legacy_v2_right_sizing.csv`, and `legacy_v2_electrical_risk_summary_frozen_2026-07-19.csv`. That object is loaded into memory at `app.js:870` and then only `site_count` and `schema_version` are used (`app.js:872`). The rail footer reads `12 sites · schema fcf3d/1.0.0` - no mode, no source, no freeze date. `metadata.generated_at`, `score_min`, `score_max`, `sources`, `disclaimer`, and `warnings` are all silently discarded. **There is no data-mode indicator at any prominence.**

**F4 - `manifest.json` is dead: the strongest disclaimer in the tree is never displayed. (HIGH)**
`manifest.json:17` carries the full disclaimer ("Planning prototype only. Screening-class estimates; not an engineering, permitting, or procurement tool. Electrical service capacity is unconfirmed for all sites pending utility/facility review."). `app.js` never fetches `manifest.json` (no occurrence of the string), and the identical copy embedded at `sites.geojson` → `metadata.disclaimer` is read into `meta` and ignored. What the user actually sees is the much weaker `Planning prototype. Screening-class estimates only.` (`app.js:873`) at 10.5 px in `--ink-3` (`#66707e`), plus a fuller sentence buried in the comparison modal (`app.js:794–796`) that requires pinning two sites to reach.

**F5 - Two of the four expected disclaimers are entirely absent. (HIGH)**
(a) **"0/12 High confidence"** appears nowhere in `web/`. The data supports it: `confidence_band` is `Medium confidence` ×8 and `Low confidence` ×4, **zero High**. The viewer shows the per-site band as a bare chip (`app.js:529`) with no scale and no portfolio context.
(b) **"Massing is not a design"** appears nowhere. The only occurrence of "massing" is `app.js:486`, an instruction inside the placement editor: `Nudge the massing onto the actual parking area you'd use.` Twelve shadowed, silhouetted 3D canopies sit on real satellite imagery at real addresses with nothing telling the viewer they are schematic volumes. This is the single largest over-certainty risk in the viewer and it directly violates `CLAUDE.md` non-negotiable #4 ("Do not let UI polish imply more certainty than the data supports").

**F6 - `score_reconstructed` disagrees with `readiness_score` for PWC005, and the UI asserts they agree with a hardcoded checkmark. (HIGH)**
`sites.geojson`: PWC005 has `readiness_score` 36.9 and `score_reconstructed` 37.0 (Δ 0.1; all 11 other sites are Δ 0.0). `app.js:578–580` renders, unconditionally:
`Σ contributions = ${num(p.score_reconstructed, 1)} = readiness score ✓`
On PWC005 this prints `Σ contributions = 37.0 = readiness score ✓` in the same tab whose header shows `36.9`. The `✓` is a literal in the template, not a computed assertion - the viewer claims a reconciliation it never performs. `CLAUDE.md` non-negotiable #2 says a silent drift here "means the map tells planners a story the model never told."

**F7 - Unpinned CesiumJS CDN contradicts its own adjacent comment. (HIGH)**
`index.html:9–12` says "Google Photorealistic 3D Tiles require 1.124 or later. For a reproducible build, pin the version: https://cesium.com/downloads/cesiumjs/releases/1.128/Build/Cesium/Cesium.js and vendor it into web/vendor/". `index.html:117` and `:14` then load `https://unpkg.com/cesium/Build/Cesium/Cesium.js` and `.../Widgets/widgets.css` - **no version, different host, not vendored, and `web/vendor/` does not exist**. Verified live: the unversioned URL 302s to `/cesium@1.143.0/...` with `cache-control: max-age=60`. So the ≥ 1.124 constraint is satisfied *only incidentally* by whatever npm `latest` is at page-load time, and the served version can change within a minute with no repo change. No SRI hash on either reference. Two separate unversioned URLs can in principle resolve to different versions.
Corrections to the brief's premise, both material: (i) the reference is in **`index.html`, not `app.js`**; (ii) the Cesium API `app.js:208` calls (`createGooglePhotorealistic3DTileset()`, zero args) **is still valid** in current Cesium - the 1.125 deprecation / 1.126 removal affected only the positional `createGooglePhotorealistic3DTileset(key)` form.

**F8 - The site list is unusable by keyboard; pinning is unreachable without a mouse. (HIGH)**
`app.js:407–425` builds bare `<li>` with `li.onclick`, no `tabindex`, no `role`, no keydown. Selecting a site - the app's primary action - is mouse-only. Pinning is bound to `li.oncontextmenu` (right-click, line 423) or the `c` key (line 831), but `c` requires `state.selected`, which only a mouse click can set. No focus management on `#panel`/`#modal`/`#tokenGate`; no `role="dialog"`/`aria-modal`/focus trap; no `:focus-visible` rule anywhere in `style.css`; `#toast` is not a live region so every error is silent to screen readers; the placement-editor `<label>`s at `app.js:491/496/501/506` have no `for=` and are not ancestors of their inputs, so they name nothing; the Cesium canvas and the rank-number pin canvases have no text alternative.

**F9 - No `prefers-reduced-motion` support. (MEDIUM)**
`style.css` has no `@media (prefers-reduced-motion)` block. `flyHome()` runs a 2.2 s camera flight unconditionally at startup (`app.js:868`, duration `2.2` at line 376) and `flyTo()` a 2.0 s flight on every selection (`app.js:368`). Users with vestibular sensitivity get a forced 3D camera swoop with no opt-out.

**F10 - The documented file:// fallback cannot work. (MEDIUM)**
`app.js:87–88` claims the inline copy lets the app "run straight off the filesystem with no web server." It cannot: `index.html:118` loads `app.js` as `type="module"`, and browsers block module scripts over `file://`, so `app.js` never runs; the `import('./data/sites.inline.js')` at line 97 is blocked for the same reason; and no `<script>` tag in `index.html` loads `sites.inline.js`, so `window.__FCF_SITES__` (line 94) is never set independently. `sites.inline.js` is 167 KB of generated payload that nothing can currently reach. The error string at `app.js:101–104` ("serve this directory … rather than opening the file directly") **contradicts the line-87 comment three lines above it**; the error string is the correct one.

**F11 - GeoJSON carries a `crs` member, removed from the spec by RFC 7946. (MEDIUM)**
`sites.geojson` top level includes `"crs": {"type":"name","properties":{"name":"urn:ogc:def:crs:OGC:1.3/CRS84"}}`. RFC 7946 §4 removed `crs`; coordinates are unconditionally CRS84. The declared value is CRS84 so nothing is semantically wrong, but a strict validator will reject it. A non-standard top-level `"name"` member is also present. Everything else validates cleanly (12 Features, all Points, all `[lon, lat, 0.0]`, all in range, all in NoVA).

**F12 - `coordinate_provenance` is present on only 6 of 12 features. (MEDIUM)**
Present on FFX002, FFX001, PWC002, PWC004, PWC001, PWC003; absent on FFX004, PWC006, PWC007, FFX003, PWC008, PWC005. The panel silently omits the "Coordinate provenance" section for the missing half (`app.js:566` ternary), so half the portfolio shows sourced, official-quality coordinates and half shows nothing - with no statement that provenance is unknown for those. Coordinate precision also varies (7 dp on FFX003 and PWC008, 6 dp elsewhere), suggesting two ingest paths.

**F13 - No authored attribution for OSM, Google, or Cesium; the required credit widget is deliberately de-emphasised. (MEDIUM)**
There is no ODbL string, no "© OpenStreetMap contributors", and no Google Photorealistic 3D Tiles branding string anywhere in `web/`. All attribution is delegated to Cesium's `.cesium-widget-credits`, which `style.css:51–54` then restyles to `font-size: 10px !important; opacity: .65` with links at `--ink-2` (`#9aa5b4`) over `#0c0e11`. The CSS comment at line 45 explicitly acknowledges the credit "is required" and then shrinks it. Separately, `app.js:148–150` points `OpenStreetMapImageryProvider` directly at `https://tile.openstreetmap.org/` - the OSMF tile usage policy prohibits using those tiles for systematic/heavy application use, which is a real constraint for a publicly deployed planning tool (Phase 8).

**F14 - Google Photorealistic 3D Tiles is called without the geocoder acknowledgement, and the geocoder is disabled. (MEDIUM)**
`app.js:208` calls `Cesium.createGooglePhotorealistic3DTileset()` with no `apiOptions`. Current CesiumJS emits a one-time console warning when `onlyUsingWithGoogleGeocoder: true` is not passed, reflecting a Google Maps Platform restriction that the tiles be used only with the Google geocoder. `app.js:156` sets `geocoder: false`. Not a crash, but a licensing question that should be resolved before any public deploy.

**F15 - Dead CSS reveals an unfinished feature: pinned sites are invisible in the rail. (LOW)**
`style.css:125` defines `#siteList li.pinned::after { content: "PIN"; }` but `app.js` never adds a `pinned` class (only `selected`, line 408). Pinning a site produces a tray chip but no indication in the list it came from.

**F16 - The comparison modal green-highlights the worst value on two rows. (LOW)**
`app.js:784` picks `Math.max` for every non-text row, and `app.js:791` tells the user `green marks the highest value in each numeric row`. For `Mean wait (min)` (row 18) and `Install cost (screening)` (row 19), highest is worst - the modal will visually endorse the slowest and most expensive site.

**F17 - `SUBSCORE_WEIGHTS` is an unguarded third copy of the model weights. (LOW)**
`app.js:26–31` duplicates `demand 0.45 / feasibility 0.30 / safety 0.15 / equity 0.10`. `CLAUDE.md` states these mirror `fcf3d/build_sites.py`, which mirrors `fcf_m2/scoring.py`, and that `test_attribution_reproduces_model_score` guards the Python copy. **Nothing guards the JS copy** - the 46-test suite is Python-only and there is no JS test runner in the tree. The tier colour palette is likewise duplicated between `app.js:18–24` and `style.css:19–22`.

**F18 - The placement editor emits a key that is not in the contract, and cannot be undone. (LOW)**
`app.js:695` emits `height_offset_m` in the "Copy placement JSON" payload; the generated `asset` dict has no such key (it has `model`, `heading_deg`, `offset_east_m`, `offset_north_m`, `clamp_to_ground`, `ports`, `pathway_ports`). Pasting the emitted JSON back into `sites.geojson` as `app.js:488` instructs would add an orphan field that `placementFor` (line 240) never reads. Separately, all 12 sites currently have `heading_deg/offset_east_m/offset_north_m` = `0.0`, so no placement work has ever been committed back.

**F19 - A saved bad ion token is unrecoverable from the UI. (LOW)**
`app.js:879–880`: if `localStorage['fcf3d.ionToken']` exists, `boot()` starts with it and returns before the gate is shown. There is no "clear token" control. The toast at `app.js:193` advises "Reload and add one to enable it", which is impossible once a token is stored. An expired or typo'd token permanently degrades the app short of devtools.

**F20 - `metadata.warnings` is never checked. (LOW)**
`sites.geojson` → `metadata.warnings` is `[]` today. `app.js` never reads it, so if the ETL ever emits a warning the viewer will render normally and say nothing.
