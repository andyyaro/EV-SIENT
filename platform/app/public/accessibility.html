Accessibility of the EV-SIENT Planner

The EV-SIENT Planner aims to meet the Web Content Accessibility Guidelines (WCAG) 2.1 and 2.2 at Level AA.

This report is self-assessed by the project team, not independently audited. It was written on 18 October 2026 for the planner at app.futurecity.andyyaro.com, app version 0.1.0 with engine version 3.0.0.

How it was checked

  • Automated checks with axe-core 4.13.0 on every screen, in Chromium and WebKit, at desktop and phone widths, in the light, dark and both increased contrast themes.
  • Every screen used by keyboard alone, with the focus order, focus visibility and the contrast of focus rings, borders and chart marks measured in all four themes.
  • Manual checks for zoom to 400 percent, text spacing, hover content, target size, error messages, status messages and the downloaded HTML, PDF and Word reports.
  • Screen readers were not tested. That work is planned with NVDA, JAWS, VoiceOver and TalkBack.

Known issues

  • Map colours. When the map colours sites by one of your own columns, the colour is the only cue you can see on the map. The value is in each marker's name for screen readers, and the column can be shown in the results table. (1.4.1)
  • Map panning. Moving the map needs a drag, or two fingers on a touch screen. The arrow keys pan it, and the results table lists every site. (2.5.1, 2.5.7)
  • Step menu on narrow screens. Choosing a step in the compact step menu goes to that step straight away. (3.2.2)
  • Your Index chart with wider text spacing. Some labels on the rank change chart are cut off when letter and word spacing are increased. The table beside it holds the same data. (1.4.12)
  • The PDF report. It is tagged, with headings, a title and a language, but row headers in its tables are tagged as ordinary cells, and the title is not set as the window title. The HTML and Word reports do not have these problems. (1.3.1, 2.4.2)

The full report

The full Accessibility Conformance Report follows the ITI VPAT 2.5 format and gives a result and remarks for every criterion. It is kept with the project's source code at docs/accessibility/ACR.md, with the evidence behind it.
